# Security Policy

## Reporting

Do not open a public issue containing a secret, personal data, or confidential business information. Use GitHub's private vulnerability-reporting feature when it is enabled for the repository.

## Data handling

This project is designed for public, fictional examples. Before using it inside an organization, define approved data sources, access controls, retention rules, and a human approval process. Never commit live credentials, connection exports, customer records, employee records, or internal process data.

If private material is committed, removing it in a later commit is not sufficient because it remains in history. Revoke exposed credentials immediately and rewrite the affected history before republishing.
